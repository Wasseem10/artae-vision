# Primary pose continuity: adjacent-frame diagnosis

October 14, 2026. The earlier [nine-frame overlay audit](mpfdd-pose-overlay-audit.md)
showed that primary ID 1 outlines different people at five and seven seconds.
This follow-up captures the intervening samples and adds a validated scorer
that preserves uncertain associations. It changes research tooling, not the
live detector. The published fall result remains **2/22 clips**.

## Fixed window and capture

Before inference, freeze [21 requested times](benchmarks/mpfdd-primary-continuity-samples-v1.json)
from 5.0 through 7.0 seconds in `mpfdd-s3-p4-f1-fall-2`, an already examined
classroom clip. Its source frame rate is 20 FPS. Replay all 71 samples from
0.0 through 7.0 at 0.1-second intervals with a fresh four-pose worker and
fused rule; retain only the selected 21 overlays. This preserves warmup.

The clean capture revision is `ac51b8a524d937eac900d266c5e0fb07d029e91f`;
Chrome is `155.0.8059.79`. The harness verifies each presented timestamp
within 1 ms before inference. All 21 retained timestamps equal their requested
times. Model, worker, rule, runtime, video, manifest, selection, and capture
hashes are recorded. Both checkout cleanliness and revision are checked before
and after capture. Each run has a unique ignored output directory so a failed
run cannot overwrite the previous successful capture.

All 21 overlays were visually inspected in contact sheets, with the 6.1–6.7
boundary enlarged individually. A repeat after normalizing the selection file
to its committed LF encoding produced identical hashes for all 21 overlay
images. The LF-input capture is the report's reference; this repeat is a local
consistency check, not another independent evaluation. Dirty-checkout attempts
were rejected before inference.

## What the adjacent frames show

These are **provisional AI visual associations awaiting independent human
adjudication**. Actor names below describe appearance within this clip only.

| Requested times | Provisional primary association | Primary ID |
| --- | --- | --- |
| 5.0–6.1 s (12 frames) | Dark-clothed person near the right curtain | 1 |
| 6.2–6.5 s (4 frames) | Ambiguous: overlapping people and mixed/transitioning limbs or torso | 1 |
| 6.6–7.0 s (5 frames) | Foreground person in blue top and gray trousers | 1 |

The endpoints support a change in which person the primary observation follows
while its slot ID remains unchanged. They do **not** establish the exact switch
timestamp or a correctly associated person during the four ambiguous frames.
`FusedMultiPersonFallRule.update` always emits primary `id: 1` and feeds the
primary temporal/window rules without a person-association gate. A stable slot
number therefore does not establish person continuity. This capture does not
demonstrate that the switch caused an alert or a missed fall.

The [provisional labels](benchmarks/mpfdd-primary-continuity-labels-v1.json)
bind every annotation to the capture and overlay hashes. The
[derived report](benchmarks/mpfdd-primary-continuity-audit-v1.json) records
17 matched frames, four ambiguous frames, and zero unobserved primary frames.
Of 20 adjacent pairs, 15 have two definite associations; all 15 follow the same
person. The other five pairs remain unknown. The scorer reports **zero direct
same-ID/different-person adjacent pairs** because it does not bridge ambiguity.
That zero is not evidence of correct identity tracking across the whole window.
This is not an ID-switch, IDF1, person recall, or fall-accuracy benchmark.

Raw/usable/fused counts match the archived observation export at **16/21
frames**. Differences at 5.2, 5.3, 5.4, 5.7, and 6.0 seconds remain in the report.
The old export did not verify presented frames, and browser/runtime differences
have not been isolated for these five count changes. Do not interpret them as
an improvement. No detector, alert threshold, model, landing page, or `/live`
workflow changed.

## Verification and local reproduction

Seven new Node tests cover provenance mismatch, changed overlays, incomplete
annotations, stale/unordered/mixed-clip times, inconsistent primary observations,
unknown actors, reused versus new IDs, and uncertainty handling. The seven
existing Python count-audit tests also pass. Node syntax checks and
`git diff --check` pass. All retained PNG hashes were verified against the
capture; the compact report was regenerated byte for byte. Visual checks are of
scientific overlays; there is no web UI change to inspect.

Use the exact pinned inputs described in the earlier overlay audit. At the clean
capture revision, run:

```powershell
node scripts/capture-mpfdd-pose-overlays.cjs `
  --media-root apps/web/public/vision/mpfdd `
  --vision-root apps/web/public/vision `
  --dependencies-root apps/web `
  --reference-report artifacts/mpfdd/evaluation-multiperson.json `
  --samples docs/benchmarks/mpfdd-primary-continuity-samples-v1.json `
  --output-dir artifacts/mpfdd-primary-continuity
```

The script prints the unique output directory. Review the overlays and create
annotations bound to **that capture's** hashes. Published annotations cannot be
silently reused for a different capture, even if the requested times match.
To reproduce the derived report from the archived capture and its labels:

```powershell
node scripts/score-primary-continuity.cjs `
  artifacts/mpfdd-primary-continuity/capture-FOM0Hx/capture.json `
  docs/benchmarks/mpfdd-primary-continuity-labels-v1.json `
  artifacts/mpfdd-primary-continuity/reproduced.json
node --test tests/benchmarks/primary-continuity.test.cjs
python -m unittest discover -s tests/benchmarks -p test_visible_person_audit.py
```

Source videos, overlays, and full landmarks remain local and ignored because
redistribution rights are unresolved. The public derived report cannot replace
access to the local overlays for independent adjudication.

# Retain detection provenance when reopening account history

November 11, 2026. The history merge now retains a matching local event's
`detectionSource` when the account event omits it. This prevents an incident
recorded with temporal-rule and pose-window agreement from losing that
provenance when reopened and exported.

## Reproduced failure and fix

At `6cd7887`, `mergeSession` replaced matching local events with account events
wholesale. `loadCloudSession` does not return the local `detectionSource`, so
the report builder fell back to describing only the temporal rule.

The merge now recovers only the missing detection-source field, matching the
event ID after the existing session-ID and account-scope checks. An explicit
account detection source takes precedence. The account event still supplies
review decisions, notes, delivery results, timestamps and saved status; local
review or delivery fields are not copied back over it. Neither input is mutated.

## Verification

- A mocked account-load test exercises `loadCloudSession` through `mergeSession`
  and report generation. The local fixture records rule agreement and an older
  acknowledged review; the account fixture records a resolved false alarm and
  failed SMS status. The merged report retains the agreement and uses the newer
  account review/delivery data.
- Two further regression cases cover explicit account provenance, an unrelated
  event ID, a different session ID and a different account scope.
- All **102 web unit tests**, TypeScript, ESLint and the production build pass.
  Run `pnpm test` from `apps/web`; the new cases are in
  `src/lib/browser-sessions.test.ts`.
- A local synthetic comparison using the old and new merge implementations
  reproduces the report text changing from temporal-rule-only to the recorded
  agreement, with the account's false-alarm decision retained.
- Chromium 153.0.8010.12 renders the resulting export at 1100 px and 390 px with
  no horizontal overflow, page errors or network requests. Both provenance
  screenshots were inspected. Local output is in ignored
  `artifacts/history-provenance/`, generated by
  `artifacts/check-history-provenance.cjs`.

## Limits

These are synthetic history/report fixtures, not production account requests
or detector evaluations. A cloud-only load or another device without the local
record still cannot recover omitted inference provenance. The fix preserves
what was recorded; it does not prove that the source label, track association
or detected fall was correct. It does not change inference, alert thresholds,
the landing page or the `/live` workflow. Independent person labels and untouched
multi-person footage remain the next detector gate.
